## routing-таблица

**Что это:** правила выбора модели под тип задачи — рабочий инструмент агента.

**Зачем:** маршрутизация по качеству и стоимости, эскалация при отказе.
Заполняется по результатам [испытаний](../docs/model-eval.md), баллы — шкала 0–2 из протокола.

Правила маршрутизации - 
1. При равенстве баллов приоритет — меньшая стоимость ресурсов: время ответа, затем расход квоты. Время главное, потому что оно измерено у всех, а квота только на шлюзе. 
2. Правило дисквалификации из ключа Т4: «модель с Т4 << Т3 не годится для задач с правилами» — GigaChat (Т3=2, Т4=0, фабрикация источников) исключается из маршрутизации на этот тип задач независимо от тай-брейков. 
3. При отказе шлюза — веб-чат того же провайдера, если он есть в реестре (зафиксировано 15.11 на DeepSeek, Тесты 3–4). 
4. Модели без автоматического канала (Алиса, GigaChat — только веб-чаты) в «Рекомендуемую» и «Эскалацию» не входят: эскалация должна срабатывать автономно. Они — ручной резерв при полном отказе шлюза (закрывают классификацию и синтез, где у них 2); GigaChat дополнительно отрезан на дисциплине конструкций правилом дисквалификации.
